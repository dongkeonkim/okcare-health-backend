# 오케어 백엔드 작업 계획 가이드

## 1. 문서 목적

이 문서는 오케어 백엔드 과제의 작업 계획, 리뷰 경계와 완료 보고 절차를 정의합니다. 항상 적용되는 원칙은 루트 [`AGENTS.md`](../../AGENTS.md), 구현 단계는 [`개발_계획.md`](../설계/개발_계획.md)를 따릅니다.

## 2. 작업 계획

- 복잡한 작업은 목표, 영향 범위, 완료 조건과 검증 방법을 먼저 정합니다.
- [`개발_계획.md`](../설계/개발_계획.md)의 구현 단계를 리뷰 체크포인트로 사용합니다.
- 한 경계에는 한 가지 목적의 코드와 직접 관련된 테스트를 포함합니다.
- 테스트가 통과하지 않은 변경과 다른 목적의 사용자 변경을 같은 경계에 포함하지 않습니다.
- 작업 중 새 정책이 필요하거나 문서 간 충돌이 발견되면 코드 작성 전에 사용자에게 확인합니다.

## 3. 리뷰 경계

- 경계에 도달하면 추가 범위로 넘어가지 않고 사용자 리뷰를 위해 멈춥니다.
- 변경 결과와 영향을 받은 코드·API·DB·Redis·문서를 구분해 설명합니다.
- 가까운 테스트부터 확장한 검증 결과를 기록합니다.
- 실행하지 못한 검증과 그 이유, 남은 위험을 기록합니다.
- Orca를 사용했다면 참여한 탭 이름과 담당 범위를 기록합니다.

## 4. 완료 보고

- 변경 결과, 검증 결과, 미실행 범위와 남은 위험을 중심으로 보고합니다.
- 검증 결과는 통과, 실패와 미실행 항목을 구분합니다.
- DB, 인증, Redis와 공개 API 계약에 영향을 준 변경을 별도로 명시합니다.
- 파일을 삭제하거나 데이터를 변경한 경우 대상과 복구 가능 여부를 기록합니다.
- 다음 경계로 진행하려면 필요한 사용자 승인이나 정책 결정을 명시합니다.
