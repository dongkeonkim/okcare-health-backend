# 오케어 백엔드 문서 작성 가이드

## 1. 문서 목적

이 문서는 오케어 백엔드 과제 문서의 독자, 책임과 동기화 규칙을 정의한다. 같은 규칙을 여러 문서에 복제하지 않고 기준 문서를 링크한다.

## 3. 작성 원칙

- 비즈니스 기획은 간결한 자연어로 핵심 문제, 가치와 사용자 흐름을 설명한다.
- 기능 명세는 구현 방법보다 외부에서 관찰되는 동작과 예외를 명확히 정의한다.
- 개발 계획은 승인된 기능을 어떻게 구현하고 검증할지 기술한다.
- 독자가 다른 문서를 함께 읽어야 하면 내용을 복제하지 않고 직접 링크한다.
- 상대 링크, 코드 블록, 줄 끝 공백과 현재 코드 또는 승인된 계획과의 일관성을 검증한다.
- 입력 데이터 건수와 회귀값은 [`기능_명세.md`](../명세/기능_명세.md)의 회귀 기준을 단일 기준으로 사용하고 다른 문서에 다른 값을 적지 않는다.
- 문서를 명확하게 다듬는 과정에서 승인되지 않은 기능이나 정책을 추가하지 않는다.
- 현재 동작과 일치하지 않는 예정·완료 표현을 남기지 않는다.
- 개인 경로, 로컬 메모, secret과 도구 전용 설정을 공개 문서에 노출하지 않는다.

## 4. 변경 동기화

- 사용자 가치나 범위가 바뀌면 `비즈니스_기획.md`를 갱신한다.
- API, 검증, 인증, 소유권, 멱등성, 집계와 오류 정책이 바뀌면 `기능_명세.md`를 갱신한다.
- 코드 구조, DB, Redis, Docker, 테스트와 구현 순서가 바뀌면 `개발_계획.md`를 갱신한다.
- 제출 산출물 구성이 바뀌면 `개발_계획.md` §13을 갱신한다.
- 코드와 기능 계약이 함께 바뀌면 같은 변경 경계에서 문서를 갱신한다.
- 문서 파일명을 변경하면 모든 링크와 `.agents/`, `.claude/`의 스킬·규칙 참조를 함께 갱신한다.
- 작업 원칙, 스킬 라우팅과 자동 강제 규칙이 바뀌면 `AGENTS.md`와 `CLAUDE.md`를 함께 확인한다.
