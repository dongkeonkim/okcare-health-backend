# 오케어 백엔드 Orca 오케스트레이션 가이드

## 1. 문서 목적

이 문서는 오케어 백엔드 과제에서 Orca를 사용해 작업을 분해하고 사용자에게 보이는 작업자 탭을 운영하는 규칙을 정의한다.

## 2. 기본 구성

- 병렬화 이점이 있으면 Orca 오케스트레이션으로 별도 Codex 또는 Claude 탭을 생성한다.
- 실제 Orca 오케스트레이션과 사용자에게 보이는 탭을 사용하며 내부 작업자 방식으로 대체하지 않는다.
- 총괄 탭 이름은 `오케스트레이터`로 고정한다.
- 작업자와의 소통 및 결과 보고에서는 탭 이름을 식별자로 사용한다.
- `오케스트레이터`는 Codex 5.6 Sol high 모델을 사용한다.

## 3. 모델 선택

- 작업 복잡도, 의존성, 위험과 검증 범위를 `오케스트레이터`가 판단한다.
- 복잡한 작업은 Claude Opus 5 또는 Codex 5.6 Sol high에 배정한다.
- 단순한 작업은 Codex 5.6 Terra xhigh 또는 Claude Sonnet 5에 배정한다.
- 독립적으로 수행할 수 있고 병렬화 이점이 있는 구체적인 작업만 별도 탭에 배정한다.

## 4. 오케스트레이터 책임

- 작업을 독립적인 하위 목표로 분해한다.
- 탭별 책임, 영향 범위, 완료 조건과 검증 방법을 지정한다.
- 진행을 대기하고 작업 간 충돌을 조정한다.
- 작업자 결과를 직접 검증한 뒤 최종 결과에 통합한다.
- 모든 작업자가 루트 [`AGENTS.md`](../../AGENTS.md)와 관련 구현 계약을 동일하게 준수하도록 한다.
- 승인되지 않은 정책을 작업자가 독자적으로 추가하지 못하게 한다.
- 경계 보고에는 참여한 탭 이름, 담당 범위, 검증 결과와 미완료 위험을 포함한다.
