# 오케어 건강활동 데이터 수집 서비스 기획

## 문서 목적

이 문서는 오케어 건강활동 데이터 수집 서비스의 문제, 사용자 가치, 범위와 성공 기준을 정의합니다.
과제 범위는 [`과제_원문.md`](./과제_원문.md)를 따르며, 요구사항 추적은
[`요구사항_추적표.md`](./요구사항_추적표.md), 기술 구현과 상세 API 계약은 각각
[`개발_계획.md`](../설계/개발_계획.md)와 [`기능_명세.md`](../명세/기능_명세.md)에서 다룹니다.

## 문제

삼성헬스와 Apple Health에서 전달되는 건강활동 데이터는 형식, 시간 표현과 숫자 타입이 서로 달라 그대로 저장하면 중복과 집계 오류가 발생할 수 있습니다. 회원별 데이터가 분리되어야 하며, 같은 데이터가 반복 전송되어도 결과가 달라지지 않아야 합니다.

## 목표

회원이 가입·로그인 후 자신의 건강활동 데이터를 전달하고, 공급자 형식과 관계없이 일간·월간 걸음수,
소모 칼로리와 이동거리를 일관된 기준으로 조회할 수 있게 합니다.

## 핵심 사용자 흐름

회원가입·로그인 → 건강활동 데이터 전송 및 최초 `recordkey`의 회원 귀속 → 재전송 데이터의 중복 방지와 변경값 반영 → 기간별 Daily·Monthly 집계 조회 순서입니다.

## 범위

이번 과제에는 회원가입, 로그인, 로그인 상태 갱신과 로그아웃, 건강 데이터 저장, 재전송 중복 방지, 일간·월간 조회가 포함됩니다.

소셜 로그인, 이메일 인증, 비밀번호 찾기, 관리자 화면과 사용자 지정 시간대 집계는 포함하지 않습니다.

## 성공 기준

제공된 네 입력 파일의 모든 레코드를 저장하고, 같은 파일을 재전송해도 저장 건수가 증가하지 않습니다. 변경된 측정값을 반영하고 `recordkey`별 회원 데이터 소유권을 분리하며, Daily·Monthly 집계 결과를 사전 검증한 기준과 일치시킵니다. 인증 정보를 안전하게 처리합니다.
