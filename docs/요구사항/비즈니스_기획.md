# 오케어 건강활동 데이터 수집 서비스 기획

## 기준

기술을 바꿔도 유효한 서비스의 목적, 사용자 가치, 범위와 성공 기준을 간결한 자연어로 기록한다.

## 문서 목적

이 문서는 오케어 건강활동 데이터 수집 서비스가 해결하려는 문제와 제공해야 할 핵심 가치를 설명한다. 기술 구현 방식과 상세 API 계약은 각각 [`개발_계획.md`](../설계/개발_계획.md)와 [`기능_명세.md`](../명세/기능_명세.md)에서 다룬다.

## 배경

오케어는 회원의 건강활동 정보를 기반으로 서비스를 제공한다. 삼성헬스와 Apple Health에서 전달되는 데이터는 형식과 시간 표현, 숫자 타입이 서로 다르기 때문에 그대로 저장하면 중복과 집계 오류가 발생할 수 있다.

서비스는 서로 다른 공급자의 건강활동 데이터를 일관된 기준으로 수집하고 보존해야 한다. 회원은 자신에게 연결된 데이터만 조회할 수 있어야 하며, 같은 데이터가 반복 전송되더라도 결과가 달라지지 않아야 한다.

## 목표

회원이 가입하고 로그인한 뒤 자신의 건강활동 데이터를 서비스에 전달할 수 있게 한다. 서비스는 서로 다른 공급자의 입력을 일관된 형식으로 정리해 안전하게 보존한다.

회원은 자신에게 연결된 데이터의 일간·월간 걸음수, 소모 칼로리와 이동거리를 조회할 수 있어야 한다. 재전송과 동시 요청에도 중복을 방지하고, 일시적인 보조 시스템 장애가 발생해도 저장된 데이터 조회는 계속 제공한다.

## 핵심 사용자 흐름

회원은 이름, 닉네임, 이메일과 비밀번호로 가입한다. 로그인에 성공하면 인증 토큰을 발급받는다.

인증된 회원이 처음 건강 데이터를 전송하면 해당 데이터 연결은 그 회원에게 귀속된다. 이후에는 같은 회원만 연결된 데이터를 저장하고 조회할 수 있다.

건강 데이터가 다시 전송되어도 같은 내용이 중복 저장되지 않아야 한다. 기존 측정값이 변경된 경우에는 수정된 값이 반영되어야 한다.

회원은 기간을 지정해 일간 또는 월간 집계를 조회한다. 공급자별 원본 형식 차이와 관계없이 일관된 기준의 결과를 제공한다.

## 범위

이번 과제에는 회원가입, 로그인, 로그인 상태 갱신과 로그아웃, 건강 데이터 저장, 재전송 중복 방지, 일간·월간 조회가 포함된다.

소셜 로그인, 이메일 인증, 비밀번호 찾기, 관리자 화면과 국가별 임의 시간대 집계는 포함하지 않는다.

## 성공 기준

제공된 네 입력 파일의 모든 레코드가 빠짐없이 저장되고 같은 파일을 다시 보내도 데이터 수가 증가하지 않아야 한다. 측정값의 저장 정밀도는 [`기능_명세.md`](../명세/기능_명세.md)를 따른다. 일간·월간 집계는 사전에 검증한 회귀값과 일치해야 한다.

회원 간 데이터 소유권이 분리되고 인증 정보가 안전하게 처리되어야 한다.
