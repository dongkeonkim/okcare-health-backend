## 2. 공통 실행 명령

```bash
# 단위·슬라이스·통합 테스트와 패키징
./gradlew clean build

# 실행 환경 기동
cp .env.example .env
docker compose up --build -d
docker compose ps

# 기동 확인
curl --fail http://localhost:8080/actuator/health
```

데이터를 보존한 종료와 볼륨 제거를 구분한다.

```bash
docker compose down

# 데이터 제거가 명시적으로 필요한 경우에만 실행
docker compose down --volumes
```

## 5. 알려진 환경 문제

### 5.1 베이스 이미지 메타데이터 해석 지연

`docker compose build`가 `load metadata for docker.io/library/eclipse-temurin:17-jre` 단계에서
진행하지 않는 경우가 있었다. 원인은 애플리케이션이나 `Dockerfile`이 아니라 멀티아치 매니페스트
해석이며, 다음으로 구분했다.

- 호스트에서 Docker Hub 매니페스트 직접 조회: `200`, 0.7초
- 작은 이미지 pull: 10초 내 성공
- 플랫폼을 지정한 pull: 10초 내 성공

베이스 이미지를 플랫폼을 지정해 먼저 받아 두면 빌드가 정상 완료된다.

```bash
docker pull --platform linux/arm64 eclipse-temurin:17-jdk
docker pull --platform linux/arm64 eclipse-temurin:17-jre
```

`Dockerfile`의 `FROM`에 플랫폼을 고정하지 않는다. 고정하면 다른 아키텍처에서 에뮬레이션으로
실행되어 이식성이 오히려 나빠진다.

## 7. 남은 위험

- 같은 `recordkey`의 최초 저장이 동시에 세 번 이상 겹치고 그중 승자가 되돌아가면, 한 번뿐인 재시도도
  같은 UNIQUE 위반을 받아 `500`이 된다. 재시도 횟수를 늘려도 같은 틈은 남으므로 늘리지 않았다.
- 저장은 `steps`만 받는다. 집계가 지표를 구분하지 않아 다른 `type`이 같은 기간에 들어오면 두 배로
  계산되기 때문이다. 다른 지표를 받으려면 집계 쿼리와 인덱스에 지표 구분을 먼저 넣어야 한다.
- 서블릿 인증 API, 역할 기반 인가, 비동기나 `ERROR`·`FORWARD` dispatch를 도입하면 현재 휴면
  상태인 Spring Security 기본값이 외부 동작으로 바뀔 수 있다. 특히 인가를 Spring Security로
  옮기면 `AccessDeniedHandler`를 오류 응답 형식에 맞춰 함께 넣어야 한다.
- 로그인 실패의 응답 시간은 균등화하지 않는다. 등록되지 않은 이메일은 비밀번호 비교를 건너뛰므로
  응답 시간 차이가 남는다. 응답 내용 비노출은 충족한다.
- `.env.example`의 JWT secret은 저장소에 공개된 고정값이다. 복사해 그대로 기동하면 알려진 키를
  사용한다.
